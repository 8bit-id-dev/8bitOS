# 8bitOS — Spec 1: App Shell + Dashboard + Classroom

**Date:** 2026-09-03
**Status:** Draft for review
**Roadmap position:** Phase 1 — Foundation (first of several specs)

---

## 1. Purpose

Establish the 8bitOS application shell and ship the first end-to-end feature area: **Dashboard** and **Classroom** (class list, roster, attendance, student profile side-panel). A teacher can sign in, see today's schedule, start a class session, and mark attendance on a Huawei MatePad Mini.

**Out of Spec 1** (each its own future spec): Notes, Browser, Whiteboard, Quiz, Gradebook, Document Center, AI Assistant, Capacitor wrap, launcher mode, biometric auth, multi-tenant admin, light theme.

## 2. Goals

- Teacher can sign in and reach the Dashboard in <5s on a warm cache.
- Teacher can see today's schedule, start the next class, and mark attendance in <4 taps.
- Teacher can open a class, see the roster, view a student side-panel, and add students.
- The app shell, dark monochrome theme, and bottom Dock navigation are stable enough that all future modules can be built against them.
- Offline-first attendance: write while offline, sync when back online, no data loss.

## 3. Design system (Doc 04 + Doc 07)

- **Fonts:** Pixelify Sans (UI/headings), Inter (body).
- **Colors:** `#050505` bg, `#ffffff` fg, strict monochrome — no decorative accents.
- **Borders:** `2px solid #ffffff`, never rounded.
- **Shadow:** `4px 4px 0 0 #ffffff` (hard offset, no blur).
- **Pixel-cut corners** on cards, modals, primary buttons via `clip-path: polygon(...)`.
- **Focus ring:** `2px dashed #ffffff`.
- **Information density:** tight rows, Notion-style. Generous whitespace only on top-level screen headers.
- **Single dark theme.** No light mode in Spec 1.

## 4. Architecture (Doc 03)

```
React 18 + TypeScript + Vite 5
+ Tailwind v3.4
+ React Router v6 (HashRouter)
+ Zustand (client state)
+ TanStack Query v5 (server state)
+ @insforge/sdk (auth + database)
+ IndexedDB outbox via `idb` (offline writes)
+ vite-plugin-pwa (PWA + service worker)
+ Vitest + RTL + MSW (tests)
```

**Dev URL:** `http://localhost:5173`. Deep links like `http://localhost:5173/#/classroom/<id>` work without Vite fallback config.

**Orientation:** landscape-locked via PWA manifest. Portrait users see `[ ROTATE TABLET · LANDSCAPE ONLY ]`.

## 5. Navigation (Doc 06 §4)

Bottom Dock `h-16` with pixel-icon labels: `HOME / CLASS / TEACH / TOOLS / SYSTEM`. Spec 1 routes `HOME` and `CLASS` only; the rest are greyed with `[ SOON ]`.

## 6. Routes

| Path | Component | Auth |
| --- | --- | --- |
| `/sign-in` | `SignIn` | public |
| `/sign-up` | `SignUp` | public |
| `/` | `DashboardScreen` | required |
| `/classroom` | `ClassList` | required |
| `/classroom/:classId` | `ClassHub` (tabs: Overview / Roster) | required |
| `/classroom/:classId/attendance/:sessionId` | `AttendanceSheet` | required |
| `*` | redirect to `/` | — |

## 7. Data model (Doc decision 07)

7 tables in `public` schema, all RLS-enabled, owned by `auth.uid()`:

- `subjects`, `classes`, `class_subjects`, `students`
- `schedule_slots` (recurring weekly), `class_sessions` (one per meeting)
- `attendance_records` (per student per session, unique constraint)

Helper function `public.is_owner(uuid)` (SECURITY DEFINER) for all policies.

## 8. UX principles (Doc 05)

- Session-based mental model. `class_sessions` is the anchor.
- Auto-save. No save buttons.
- Calm UI, inline status only, no toast spam.
- One-tap `[ MULAI KBM ]` from Dashboard when a schedule slot exists.
- Context preservation across reload via URL + React Query cache.
- Recovery on launch: if outbox has unsynced rows, show `[ PULIHKAN SINDIKASI? ]`.

## 9. Offline behavior

- Service worker caches app shell — UI always loads.
- No session + offline → `[ OFFLINE · SIGN-IN REQUIRED ]` screen.
- With session + offline → reads served from React Query cache (staleTime 30s), writes go to IndexedDB outbox, flush on `online` event.
- Only `attendance_records` writes are wired through the outbox in Spec 1. Other writes fail loudly if offline.

## 10. Outbox

- IndexedDB database `8bithos-outbox`, object store `outbox` (auto-incrementing id).
- Schema: `{ id, table, op, payload, attempts, created_at }`.
- `flushOutbox()` drains oldest-first, removes on success, increments `attempts` on failure.
- Idempotency: `attendance_records` use server unique constraint `(session_id, student_id)`.

## 11. Error handling

| Surface | Behavior |
| --- | --- |
| Network error on read | Toast `[ GAGAL MEMUAT ]` + retry. 3 retries, exponential backoff. |
| Auth error (401/403) | Force sign-out, route to `/sign-in`, toast `[ SESI BERAKHIR ]`. |
| Validation error | Inline pixel alert. |
| Outbox write rejection | Leave row, increment `attempts`, after 5 attempts toast `[ PERIKSA KONEKSI ]`. |

## 12. Verification

- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` all green.
- Manual: sign up → sign in → create class → add 5 students → create session → toggle attendance → reload → persists.
- Offline toggle: outbox row appears, reconnect → row flushes.
- Lighthouse PWA audit ≥ 90.
- `npx -y @insforge/cli diagnose advisor --severity critical` → zero findings.
